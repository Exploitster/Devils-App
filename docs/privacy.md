# Privacy and deletion

Conversations are stored with account access controls. They are not end-to-end encrypted. Messages, summaries, clarification answers, card versions and saved citation associations are private account data. Shared, reviewed public source records belong to the evidence corpus and survive deletion of a conversation that cited them.

Generation sends bounded conversation context and selected evidence to the configured model provider. The server calls the Gemini API without requesting tools or explicit caching. Retention and training policies depend on the configured Google account and API terms; this app does not establish those policies. Review the actual provider agreement and settings before using sensitive data. Local development uses fake test identities and the local model adapter; it sends no real email or model request.

Saved private conversations remain until the user deletes them. Session deletion removes the session and its embedded messages, cards, summaries and evidence references, plus turn operations and committed usage. Pending completion cannot recreate a deleted session. Usage totals for deleted conversations disappear; separate provider-attempt spend remains so failures, cancellation and deletion cannot bypass spending limits.

Account closure requires a signed-in identity, same-origin request and the exact confirmation `DELETE`. The server chooses the account from the verified identity. It first disables the account and revokes pending writes, then stops renewal of any renewable subscription, deletes private saved content and invitations, clears the profile email, and removes the authentication identity. It finally clears the browser session cookie. There is no automatic refund. A failed remote step returns `DELETION_PENDING` and keeps the profile disabled and pending so the existing verified session can retry closure. Private data may already have been removed when an identity-provider step fails. Ordinary generation, history and billing actions remain blocked during closure.

A disabled pseudonymous profile ID, provider/customer/subscription links, subscription state, webhook receipts and provider-attempt token/cost accounting remain for billing reconciliation and abuse controls. Those records must not contain conversation bodies or email. Backups and external billing or model services may retain data under their own retention policies; immediate erasure of those copies is not promised. This repository does not configure or claim a specific backup retention window. Operators must define and disclose that window before production use.

The logging helper admits named events, opaque IDs, fixed error codes, elapsed time and cost. Do not log request bodies, conversation text, source payloads, provider responses, raw errors, email, cookies, credentials or authentication tokens. Health reports configuration readiness only, with no configuration values. An `ok` health response does not prove remote-service connectivity.

Local tests exercise deletion, retry failures, late writes, owner denial, cookie revocation, CSRF, input size and safe logs. The isolated PostgreSQL check applies all migrations and tests RLS with stub auth functions. Hosted Supabase admin identity deletion, real authenticated two-user RLS and actual backup/provider retention require a separately configured sandbox; local checks do not verify those claims. Local mode is forbidden in production.
